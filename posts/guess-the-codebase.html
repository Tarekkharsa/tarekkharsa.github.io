Guess the codebase?

Eight engineering lessons from one open-source repo. You guess which one.

I spent a few weeks reading one open-source codebase cover to cover: the server, the clients, the lint rules, the CI, the PR templates, even the bot configs. It's one of the best-engineered repos I've read, so I'm turning what I learned into a game.

How to play

  1. Each lesson teaches one engineering idea, using real code and docs from the repo.
  2. Each post ends with three hints about where it came from. Hints pile up from lesson to lesson.
  3. Post your guess on X with #GuessTheCodebase before you open the reveal.
  4. The finale reveals the repo and adds 30 power-user tips for actually using it.

The lessons

  • 1 · ArchitectureDecide, commit, then act2 minThe three-step server pattern that keeps AI agents from leaving your app in a weird state.
  • 2 · PerformancePerformance budgets belong in unit tests2 minSeven performance patterns from one repo's commit log, and why their budgets fail the build.
  • 3 · TestingMock the boundary, not the logic2 min“A test that needs a timeout to pass is wrong.” Testing rules from a repo that bans sleeps.
  • 4 · GitHub & PRsA PR process for the AI era2 minWhen anyone can generate a 2,000-line PR in ten minutes, review time is what you protect.
  • 5 · DX & ToolingTurn taste into lint rules1 minReview comments don't scale. A repo with 14 custom lint rules shows what does.
  • 6 · Dev setupA dev setup built for ten agents on one laptop2 minPorts, databases, processes and URLs: everything shared becomes a collision once agents run in parallel.
  • 7 · UI / UXLying spinners, stale labels, one-way doors2 minUX rules from a repo whose users stare at it all day and notice every lie the UI tells.
  • 8 · AI-native engineeringWrite docs for your most frequent contributor1 minIn this repo, the most frequent contributor is an AI agent running inside the app itself.
