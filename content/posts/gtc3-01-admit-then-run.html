Try it: the prompt inbox

send, steer, queue, retry, crash

Prompts land in the inbox first. At each turn boundary, the agent moves them into the conversation. A crash loses the running work, never the inbox.

sessions.prompt({ id, sessionID, prompt, delivery: "steer" | "queue" })
  -> same ID again: same receipt, no duplicate
  -> same ID, different prompt: fails loudly

How it works

  1. AdmitYour prompt becomes one row in a session_input table. It's saved and replayable, but the model hasn't seen it.
  2. PromoteAt the next safe boundary, one atomic step removes the row from the inbox and appends it to the conversation.
  3. RunThe model works on the conversation. If the process dies, whatever is still in the inbox is waiting for the next run.

Steer or queue

Steer (default)

Joins at the next turn boundary, while the current task keeps going.

"Also add a test."

Queue

Waits until the agent would otherwise go idle, then starts one at a time.

"After that, update the docs."

What isn't saved, on purpose

The running part, a drain, isn't a stored thing: "A Session Drain has no durable identity or transcript boundary." Interrupting stops the work but keeps the inbox, and interrupting an idle session does nothing. After a crash, recovery starts from what was saved (prompts, history, tool results), not from an invented "job" record.

Steal this

Put a durable inbox between "the user sent it" and "the model sees it." Make prompt IDs idempotent, make steer and queue explicit, and don't save the parts that are only coordination.
