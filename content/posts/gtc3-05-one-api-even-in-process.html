Most tools with both a server and an embeddable SDK end up with two APIs. The HTTP one is used by remote clients. The "local" one calls internal functions directly, because it's faster and easier. Slowly they drift: a validation that only runs over HTTP, a field only the local path returns, an auth check one of them skips.

This repo's next SDK refuses to have a second API.

A fetch that never leaves the process

const web = HttpRouter.toWebHandler(createEmbeddedRoutes(), { ... })

const fetch = (input, init) => web.handler(new Request(input, init))

const client = yield* Client.make({ baseUrl: "http://[name].local" })
  .pipe(Effect.provideService(FetchHttpClient.Fetch, fetch))
  1. Build the real routesThe embedded host builds the same server routes and turns them into a web handler, scoped so it's disposed when the host is.
  2. Swap only the transportThe generated client is given a fetch that calls the handler directly with a real Request. The base URL is a local hostname that never resolves on a network.
  3. Add only what's truly localThe embedded host extends the client with same-process capabilities, like registering application tools, instead of reimplementing the API.

Every embedded call goes through the same router and handlers as a remote one. The glossary even warns against calling it a "local implementation": it isn't one.

One source of truth, generated outward

Generated clients

Promise and Effect clients are generated from the public HTTP API. The agent guide says never to edit the generated folders by hand; change the API and regenerate.

A contract IR

A runtime-neutral compiled form of the API sits in between, so independent SDK generators can each choose their own value model and runtime.

One page shape

Pagination is a Page everywhere: items plus opaque previous and next cursor links for the same query in either direction.

Directed dependencies

"Client runtime code may depend on Schema and Protocol but never Core or Server." The client can't take a shortcut into server internals.

Steal this

If you ship an embedded mode, run it through your public API with an in-memory transport instead of calling internals. Generate the clients, forbid client imports of server code, and the two modes can't drift.
