Large codebases rot through vocabulary before they rot through code. One person says "system prompt", another says "context", a third says "instructions", and soon there are three slightly different things with the same job. Agents make it worse: they pick up whichever word they saw last and spread it to new files.

This repo's answer is a glossary file at the root that does something I'd never seen before: it tells you which words not to use.

Terms, with their banned synonyms

**System Context**:
The structured collection of contextual facts presented to the model
as initial instructions and chronological updates.
_Avoid_: System prompt

**Embedded [Product]**:
A scoped in-process host that structurally extends the Client ...
_Avoid_: Local implementation

**Page**:
A bounded ordered result containing items and opaque previous and
next cursor links ...
_Avoid_: Response envelope

24 terms, 9 of them with an Avoid line. Each banned word is the one you'd reach for naturally, and the one that would blur the design. "System prompt" suggests a single string you can rewrite; "System Context" is a set of typed sources with update rules (that's lesson 2).

Relationships, not just definitions

Below the terms is a list of relationships written as plain rules: what contains what, what happens at which boundary, what's durable and what isn't. "An Admitted Prompt is replayable pending input, not yet model-visible Session History." Each one is a sentence an agent can check its change against.

Style rules written as examples

The agent guide does the same thing for code. Instead of "write clean code", it shows short Good and Bad pairs: inline a value used once, avoid else with early returns, don't destructure just to read two fields, never alias imports. Agents follow examples better than adjectives.

Steal this

Write a glossary for your core concepts, and add an "avoid" line for each tempting synonym. Then write invariants as one-sentence rules and style as good/bad pairs. That's documentation an agent can actually obey.
