Model providers cache the start of a request. If the prefix is byte-for-byte the same as last turn, you pay a fraction of the price and wait less. Many agents break that cache every turn without noticing, because the date, the git branch or the active rules are re-rendered into the system prompt.

Try it: what the cache can reuse

green is served from the provider's cache, red is paid in full

If the system prompt changes every turn, nothing before the change can be reused, so every request is paid in full. Freeze the prompt and append small updates instead, and each turn only pays for what's new.

The model

  1. Typed context sourcesThe system context is built from Context Sources, each with a stable namespaced key, a JSON codec, a loader and pure renderers for the baseline, an update and, if needed, a removal.
  2. A frozen baseline per epochAt the start of a Context Epoch the full context is rendered once and becomes "the immutable provider-cache baseline", until a completed compaction, a session move or an incompatible change.
  3. A snapshot of what the model sawA hidden JSON snapshot stores the last value admitted for each source, so the runtime can tell exactly what changed.
  4. Appended updatesWhen a source changes, a Mid-Conversation System Message with its newly effective state is appended at the next safe boundary. The baseline is never edited.

The rules that make it correct

Lazy, not pushed

Changes are "sampled and admitted lazily at a Safe Provider-Turn Boundary, never pushed asynchronously when their source changes."

Deterministic

Producers run concurrently but combine in stable key order; duplicate keys fail. Changes at one boundary combine into a single message.

Stale beats missing

If a source can't be read right now, the previous value stays in effect and nothing is emitted. A source that's really gone can emit removal text.

Atomic and replayable

The snapshot advances in the same step as the durable update message, which stores the exact text the model was sent.

Where the epoch ends

Compaction starts a new epoch with a freshly rendered baseline and snapshot; earlier update messages stay as audit history but leave the model's view. If the initial context can't be loaded, the first turn is blocked rather than persisting an incomplete baseline, and the prompt stays in the inbox to retry.

Steal this

Render the system prompt once per epoch and never edit it. Track what the model last saw for each piece of context, append changes at turn boundaries in a stable order, and let compaction be the only thing that starts a new baseline.
