Hand-written HTTP mocks lie in a quiet way: they return the response you think the provider sends. Streaming chunk boundaries, retry headers, odd status codes and WebSocket frame order get simplified away, and those are exactly where provider bugs live. The agent guide's first testing rule is "Avoid mocks as much as possible."

So the repo built a recorder, and published it as its own package.

Record once, replay after

it.effect("loads a user", () =>
  getUser.pipe(Effect.provide(HttpRecorder.http("users/get-one"))),
)
// first local run: calls the API, writes recordings/users/get-one.json
// later runs:      replays the cassette, no network
  1. Cassette recorded?Replay it. Application code can't tell whether a response is live or replayed.
  2. Missing, running locally?Call the real service once and save the exchange as a reviewable JSON file.
  3. Missing, on CI?Fail. When CI=true a missing cassette is an error, never a live call, so tests can't quietly start hitting the network.

The details that keep it honest

No overwrite mode

To refresh a recording you delete its file and rerun. "Deletion makes the set of recordings being refreshed visible and reviewable."

Redacted before disk

Most headers are dropped, and credentials in headers, URLs and JSON bodies are redacted by default. You extend it for your own fields, like an account ID in a path.

WebSockets in order

Replay releases server frames until the next recorded client frame, then waits for the app to send a matching one. Chronology is part of the test.

Binary-safe

Binary frames are stored losslessly as base64, and client and server frame kinds must match on replay.

Where it's used

Recorded tests cover real provider streams in the core, LLM and main application packages, the place where mocks would be most misleading: a chat stream's exact chunking, a provider's error shape, a WebSocket transport's message order.

Steal this

Replace hand-written HTTP mocks with recorded cassettes. Fail in CI when one is missing, make refreshing a deliberate delete-and-rerun, and redact secrets before they're written, not after.
