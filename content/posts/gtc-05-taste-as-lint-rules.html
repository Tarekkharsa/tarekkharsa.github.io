When most of your contributors are AI agents, a review comment is the least scalable thing you have. You write it, the agent fixes it, and the next agent makes the same mistake tomorrow. This repo encodes its taste as a custom lint plugin instead: fourteen rules, each with its own test file.

Each rule encodes a real failure

RuleThe failure it prevents
no-unscoped-hasA broad CSS :has() variant makes every DOM change restyle the whole page
no-inline-schema-compileCompiling a validation schema on every call instead of once
no-hermes-unsupported-apisShared code using web APIs the mobile JS engine can't run
no-rpc-permission-bypassClient mutations skipping the permission-checked command path
no-raw-mcp-registrationAgent tools registered without declaring who may call them
prefer-catch-tagsCatch-all error handling that hides which typed error happened
no-test-in-loopTests declared in a for loop instead of it.each
no-native-title-tooltipNative title="" tooltips instead of the styled component
require-suppression-reasonAn eslint-disable or @ts-ignore with no explanation

Half of these are performance, portability or security bugs, not style. A lint rule is the cheapest place to stop a bug class: it runs before tests and review, on every change, for every contributor.

Good rules know their exceptions

The tooltip rule bans title as a tooltip on regular elements, but still allows it on iframe, embed, object, frame and math, where the attribute is the element's accessible name, not a tooltip. A blunt rule would have broken accessibility. Each exception is spelled out in the rule and covered by its tests.

Silencing a tool should cost something

  1. A reason is mandatoryEvery suppression needs a -- reason suffix or a comment on the line above. Lint enforces it.
  2. A human has to lookAny PR that adds or broadens a suppression can't be auto-approved.

Design systems need enforcement too

shadcn/no-restyle stops you restyling a shared <Button> with className. You pick a variant or size, or you add a variant to the component. Layout classes (width, margin, position) go on the parent. That's how a design system stays consistent with hundreds of contributors.

Dead code fails CI

knip runs in CI, and an export nobody imports fails the build. No "might need this later" exports, refactors actually delete old files, and there are no re-export shims.

Steal this

Each time you write the same review comment a second time, write a lint rule instead, with tests and with the exceptions spelled out. Make suppressions explain themselves and need a human to approve.
