Testing an AI agent is awkward. The interesting behavior depends on a model that's slow, costs money, needs an API key and never answers the same way twice. The easy way out is to let tests call a real model "just for the important ones." This repo closes that door.

A model that doesn't exist

The test suite runs against a faux provider: a fake LLM that streams exactly the messages a test scripts for it, tool calls included.

fauxAssistantMessage([
  fauxText("Let me look at the file."),
  fauxToolCall("read", { path: "src/app.ts" }),
])

It streams in small token-sized chunks like a real provider, so the agent loop, tool execution, retries, queues and rendering all run for real. Only the model is fake. The suite's README is blunt about it:

Do not use real provider APIs, real API keys, network calls, or paid tokens.

An environment with nothing of yours in it

Faking the model isn't enough if tests can still read your machine. The test script starts from an empty environment and adds back only an allowlist:

env -i "${test_env[@]}" npm test

# test_env includes:
HOME=$test_root/home     TZ=UTC      LANG=C
GIT_CONFIG_GLOBAL=/dev/null          GIT_ASKPASS=false
NPM_CONFIG_USERCONFIG=$test_root/npm-userconfig

A fresh home directory means no real credentials, settings or sessions. No global git config, and an askpass that always fails, means nothing can stop and prompt for a password. Fixed time zone and locale remove a whole class of "works on my machine." Even cleanup is careful: it refuses to delete any directory that doesn't carry the marker file it created.

Tests that remember why

When a bug gets fixed, its regression test is named after the issue: there are 81 files like 5208-late-bash-output.test.ts and 3317-network-connection-lost-retry.test.ts. Months later, the name still links the test to the conversation that explains it.

For MCP, CI runs the official conformance suite against the client and fails on any regression from a committed baseline, so "we support MCP" is a number that can only go up.

Steal this

Fake the model, not your code, and run tests in an environment that contains nothing of yours: no home directory, no credentials, no global config. Name regression tests after the issue so the "why" survives.
