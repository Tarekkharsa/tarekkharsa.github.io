Testing an agent is awkward. The interesting behavior depends on a model that's slow, costs money, needs a key and never answers the same way twice. The easy way out is to let tests call a real model "just for the important ones." This repo closes that door at two levels.

Level 1: a model that doesn't exist

The suite runs against a faux provider: a fake LLM that streams exactly the messages a test scripts for it, tool calls included.

fauxAssistantMessage([
  fauxText("Let me look at the file."),
  fauxToolCall("read", { path: "src/app.ts" }),
])

What's fake

Only the model. It streams in small token-sized chunks like a real provider, and can return errors and stop reasons on cue.

What's real

The agent loop, tool execution, retries, queues, sessions and rendering, all running for real against the scripted stream.

Do not use real provider APIs, real API keys, network calls, or paid tokens.

Level 2: an environment with nothing of yours in it

Faking the model isn't enough if a test can still read your machine. The test script starts from an empty environment and adds back an allowlist:

env -i "${test_env[@]}" npm test

# test_env includes:
HOME=$test_root/home     TZ=UTC      LANG=C
GIT_CONFIG_GLOBAL=/dev/null          GIT_ASKPASS=false
NPM_CONFIG_USERCONFIG=$test_root/npm-userconfig
  1. No credentials reachableA throwaway HOME means no real keys, settings or sessions, even if a test forgets to mock something.
  2. Nothing can promptNo global git config, and an askpass that always fails, so a test can't hang waiting for a password.
  3. Same result everywhereFixed time zone and locale remove a whole class of "works on my machine".
  4. Cleanup that can't hurt youThe script refuses to delete any directory that doesn't carry the marker file it created itself.

Tests that remember why

Every bug fix gets a regression test named after its issue: 81 files like 5208-late-bash-output.test.ts and 3317-network-connection-lost-retry.test.ts. Months later, the filename still leads to the conversation that explains the edge case.

For MCP, CI runs the official conformance suite against the client and fails on any regression from a committed baseline, so support can only ratchet up.

Steal this

Fake the model, not your code, and run tests in an environment that contains nothing of yours: no home directory, no credentials, no global config. Name regression tests after the issue so the "why" survives.
