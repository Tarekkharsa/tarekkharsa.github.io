Someone tried to tell me t3 code is bad and their terminal phone app was better because "ssh is encrypted"

— Theo (@theo), who made T3 Code

I laughed. Then I thought about it for longer than I'd like to admit.

SSH is encrypted. It's also great. But "it's encrypted" is a fact about the pipe, and it says nothing about what happens at either end of it.

And the pipe is a tie anyway. T3 Code over Tailscale is WireGuard. Over T3 Connect it's HTTPS. And if you really love SSH, the desktop app can connect over SSH. Same pipe.

The one fair hit: T3 Code's plain LAN pairing is HTTP. Don't use it on airport Wi-Fi. Use Tailscale.

The real test: your phone just got stolen

Encryption won't help you here, and this happens a lot more often than someone breaking WireGuard. Pick a setup:

The thief gets A shell as you. Your files, your ~/.aws, your git push, and rm -rf ~. End-to-end encrypted, at least. 🔐

You fix it by Finding every server that key can reach and deleting it from authorized_keys. Hope you remember them all.

The thief gets Whatever you gave that phone. Make it read-only and they can watch your agents work, but can't start or steer one.

You fix it by Settings → Connections → revoke that phone. Your laptop doesn't even notice.

To be fair: if you gave the phone full access, it can still start an agent in Full access mode, so that's powerful too. The point is that you get to choose less, per device. SSH technically lets you restrict keys too. Nobody does.

Four questions, not one

Next time someone says "it's secure, it's encrypted," run through these:

"It's encrypted" is the "it compiles" of security. Good to hear, and nowhere near done.

Use SSH. Use T3 Code. Use both. Just don't pick one because the pipe is encrypted. Every pipe is.

Sources, T3 Code docs: remote access, auth, permission modes.
